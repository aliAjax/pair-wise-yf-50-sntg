# pair-wise-yf-50 灾后需求评估与任务分派离线前端

源提示词摘要：评估员在弱网环境离线记录家庭需求、特殊照护和现场说明，团队负责人合并重复记录、分派复核任务并追踪进展；多人修改同一记录时提供字段级冲突展示，不静默覆盖。

## 技术栈

Nuxt3、TypeScript、Naive UI、Pinia、Nuxt路由、Axios、VueUse、VeeValidate、Zod、Vue I18n。

## 离线同步模型（字段级留痕 + 到达顺序重放）

核心实现在 `utils/sync.ts`（纯 TS，无 Vue 依赖，设备端与未来服务端共用同一套规则）：

- **按记录和字段留痕**：每次修改是一条不可变操作 `ChangeOp`，携带 `recordId`、`field`、新值、来源设备 `deviceId`、设备内序号 `deviceSeq`、操作时间 `opTime`、全局到达序号 `arrivalSeq`，以及处理结果 `effect`。
- **到达顺序重放**：联网后对端操作按 `arrivalSeq` 排序逐条归并（`replayIncoming`）。
- **不同字段自动合并**：字段各自独立基线（`fieldBasis`），A 改人数、B 改说明互不影响，不再整条覆盖，任务不会丢。
- **同一字段人工选择**：两台设备都改了同一字段且值不同时，生成 `FieldConflict`，展示旧值（基值）与各设备新值（含来源设备/到达序号），用户选择后落值；选择动作本身也按到达顺序留痕。
- **重复登记合并**：合并时源记录上的任务全部改挂到保留记录，并建立 id 别名；合并后到达的、指向旧记录的修改与任务自动转到保留记录。
- **结案闸门**：家庭存在未完成任务时，无论本机操作还是对端重放，`status=已完成` 一律拒绝；任务完成也不自动结户，必须显式结案。
- **旧版数据接续**：v1 的整条覆盖式队列缺少字段信息，迁移时标为“待核对”原样保留在操作记录中、不参与自动重放（不会覆盖数据），人工核对后销项；旧版冲突转为新的候选冲突。
- **失败重试幂等**：操作 `id` 即幂等键，`appliedCount` 记录 effect 实际执行次数（恒 ≤ 1）。ACK 丢失只改投递状态，整包重发时已见 id 直接“幂等忽略”，绝不执行两次。
- **性能**：归并为单次有序遍历（O(n) 查找用 Map/索引化结构），200 条实测约 1–3ms，远低于 2 秒目标。
- **审计**：「操作记录」面板可按处理结果过滤，每条显示到达序号、来源设备-设备序号、动作、处理结果与说明。

## 验证

```bash
npm install
npm run test:engine   # utils/sync.ts 的 45 项规则与性能断言（纯 Node 运行）
npm run dev           # 开发端口 62015
npm run build
```

引擎测试覆盖：多设备字段合并/冲突、合并转单与迟到修改、结案拦截、旧版迁移、ACK 失败与整包重试幂等、审计完整性、200 条 < 2 秒（含重复投递幂等）。

## 页面演示路径

1. 在「需求记录」选家庭，用“字段级修改”改一个字段（如地址），再点“模拟平板-B离线改同一户”——该操作包入站但未到达。
2. 到「同步队列」点“联网后按到达顺序同步/重放”：说明字段自动合并，地址字段因双方都改而进入「冲突处理」，展示旧值与两台设备的新值，人工选择后落值。
3. 「重复合并」面板合并疑似重复登记，观察任务转到保留记录。
4. 任务未全部完成时点家庭卡片上的“结案”会被拒绝。
5. 打开侧栏“弱网：随机丢 ACK”后同步，再点重试，观察失败条目的 `appliedCount` 始终为 1。
6. 点“压测：一键到达 200 条修改”查看归并耗时报告。

旧版本地缓存（localStorage 中无 `schemaVersion` 的 v1 数据）首次加载会自动迁移。
